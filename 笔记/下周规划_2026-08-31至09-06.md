# 下周规划：2026-08-31 至 2026-09-06

## 一、下周总目标

把 V3-B 从“代码和工程候选”推进为“可重复真机基线”，同时启动不破坏现有主线的完整 ACT、
六固定点和 ICRA 2027 正式证据工作。优先顺序是：安全真机验收 → 固化版本 → 对照实验 →
扩展能力。

## 二、优先级与验收门

### P0：完成 V3-B 双斜率真机验收并冻结

1. 发动机关闭完成至少 20 次 ACT→RL 交接，检查：
   - terminal-zero ACK 和 generation 单调；
   - 旧策略动作没有在新 generation 被接受；
   - 双斜率首段命令符合 `4.0/s`，稳态/反向符合 `3.0/s`；
   - 安全停止能够确认最终零命令。
2. 发动机开启按 1 铲 → 4 铲 → 7 铲逐级验证，任何一级失败都停止升级。
3. 每次保留 Experiment Run、owner/ACT/action audit 和 WebUI 日志；统计：
   - ACT→RL 第一非零 ACK p50/p95/max；
   - 首个越过液压死区命令；
   - 铲尖首次移动 5 mm 的延迟；
   - 是否出现冲击、超调、停顿或人工介入。
4. 通过后审查三仓 diff，修复阻断问题，提交并 push `zs/v3-b`，生成新的跨仓基线表。

**交付标准**：7 铲完成、零安全故障、可见动作间隙 p95 小于 1 s、版本和日志可追溯。

### P1：完整 ACT 模型保持并行，完成 commissioning

1. 不替换当前分阶段主线，以独立 WebUI 配置启动双 RGB 115K 候选。
2. 依次完成：strict manifest/hash → CUDA warmup → Shadow → 发动机关闭 20 steps → 单周期真机。
3. 检查两个相机的新鲜度、推理耗时、动作饱和率、终态判定、Fixed Dump 边界和 RL 返回。
4. 若单周期安全，再做 3 铲；失败则回滚到 V3-A/V3-B 分阶段基线，不边测边改 checkpoint。

**交付标准**：给出“可继续真机实验 / 需要补数据或改 Runtime”的证据结论，不以一次成功宣布模型有效。

### P1：三固定点扩展到六固定点

1. 先定义六个工程目标：近左、近中、近右、远左、远中、远右；坐标与采集时的口头区域语义
   对齐，但不伪造 raw 标签。
2. 只修改目标/轨迹配置，不改 ACT 模型输入、action contract 或控制权协议。
3. 在 RViz 验证六点、圆弧中点和安全高度；随后发动机关闭检查每条轨迹输出。
4. 真机逐点单铲，全部通过后再做六点轮换。自动选点属于下一阶段，不与六点 commissioning 同时做。

**交付标准**：六个固定点分别有配置、可视化、单铲日志和安全结论。

### P1：补齐 ICRA 2027 R01/R02 证据

1. 归档真实六区采集计划原文件，计算 SHA-256；建立只读 audit manifest，记录：
   - Episode 1–110 与 111–145 的作者确认任务边界；
   - 139 accepted、5 aborted、1 failed；
   - raw 中不可信的标签字段；
   - 计划表与 campaign-level 六区覆盖关系。
2. 不原地修改 raw，不用占位标签做统计分组。
3. 使用相同 parent split、seed、sample exposure 和 ACT 超参数训练 constant-image state-only 对照；
   后续增加多 seed 与独立 held-out。
4. 统一 checkpoint 选择规则，保存 validation 曲线、参数量、Orin latency 和 Runtime parity。

**交付标准**：R01/R02 对照表中每项都有 artifact 路径、hash、状态和明确缺口。
