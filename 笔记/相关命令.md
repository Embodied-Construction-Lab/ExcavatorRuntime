## 3. 开始前的互斥检查

`/dev/ttyTHS1` 同一时刻只能被 RL Runtime、Collector 或 ACT Runtime 之一占用；
`/dev/video0` 同一时刻只能被 Collector 或 ACT Runtime 之一占用。

```bash
# Orin
fuser -v /dev/ttyTHS1 || true
fuser -v /dev/video0 || true
pgrep -af 'orin_state_sender|excavator-il collect|excavator-il act-runtime' || true
```

不要用模糊 `pkill`。常规停止方式是在对应前台窗口按 `Ctrl+C`，等待终态零命令和资源释放。

## 4. STM32 与零命令验收

发动机关闭，Orin/STM32/传感器/相机上电，STM32 复位，双杆居中，deadman 释放。

PC 只读检查 USART2：

```bash
cd /home/zhaoshuai/workspace_uinty/RL_prj/excavator-il
conda activate excavator-il
python scripts/diagnose_stm32_link.py
```

继续的基本条件：

- `passed=true`；
- `parse_failure_count=0`；
- `control_sequence_gap_count=0`；
- 遥测和控制频率均约 20 Hz；
- `max_receive_period_ms <= 80`。

30 秒零命令 soak：

```bash
python scripts/run_zero_command_soak.py
```

预期 `passed=true`，且串口命令、STM32 动作回显和有效专家动作均为零。该诊断 Episode 不进入训练集。

## 5. RL 真机流程

### 5.1 纯 RL 现场验证

Orin 终端：

```bash
cd /home/jetson16/workspace_excavator/excavator-orin-runtime
conda activate excavator-orin

RUN_TAG=$(date +%Y%m%d_%H%M%S)
mkdir -p deploy/logs
python -u orin_state_sender.py \
  --serial-port /dev/ttyTHS1 \
  --control-enabled \
  --pc-host 192.168.50.1 \
  --edge-config deploy/edge_runtime.remote.json \
  --edge-motion-authorization ALLOW_EDGE_MACHINE_MOTION \
  --print-every 100 \
  2>&1 | tee "deploy/logs/rl_follow_${RUN_TAG}_stdout.log"
```

PC 终端：


这个 launch 启动感知、地图、真机状态桥、Plan/Follow Gateway、RViz 和 Mission Panel。

### 5.2 ACT 采集前的 RL 定位

先只在 PC 启动上述 `operator.launch.py`，**Orin 不要手工启动** `orin_state_sender.py`。

确认 Follow 成功并释放串口后再启动 Collector。

定位方式：

## 7. ACT Orin 推理

ACT Runtime 在 Orin 本地读取 STM32 和相机，不需要 PC teleop。日常脚本默认使用
`excavator-act-inference:jp72-pytorch261`，不需要每次手工设置 `ACT_RUNTIME_IMAGE`。

### 7.1 Shadow（不写 STM32）

```bash
# Orin
cd /home/jetson16/workspace_excavator/excavator-il
bash scripts/run_act_shadow.sh
```

看到 `ACT hardware ready: mode=shadow` 后运行至少 30 秒，按 `Ctrl+C`，然后：

```bash
bash scripts/inspect_latest_act_runtime_log.sh shadow
```

预期 `passed=true`、`serial_write_count=0`、`nonzero_serial_write_count=0`。

### 7.2 Motion（具备 STM32 写权限）

第一次或新 checkpoint 验收时必须先关闭发动机，确保 RL Runtime 和 Collector 均已停止：

```bash
# Orin
cd /home/jetson16/workspace_excavator/excavator-il
bash scripts/run_act_motion.sh
```

终端要求时输入：

```text
ALLOW_ACT_MACHINE_MOTION
```

这是显式本地启动授权，表示允许策略向 STM32 写入杆量，不是密码。停止后检查：

```bash
bash scripts/inspect_latest_act_runtime_log.sh motion
```

首次发动机开启的非零运动只能在 Shadow 和发动机关闭 Motion 都通过后进行。

重建 Orin 推理镜像、固定依赖、checkpoint 传输和离线 CUDA 推理见：

