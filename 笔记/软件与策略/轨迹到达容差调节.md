# 轨迹起点、终点与中间点到达容差调节

最后核对：2026-09-03。

这篇笔记用于调整 Resident Mission 中 RL Follow 的 waypoint 到达判定。当前活动实现会在 Orin 上把一个固定终点动态展开为：

```text
实时斗尖起点 → 圆弧中间点 → DIG 或 DUMP 最终点
```

## 1. 当前真实契约

| waypoint 类型 | 当前字段 | 当前值 | 是否能独立调整 |
|---|---|---:|---|
| 起点 | `waypoint_tolerance_m` | `0.25 m` | 否，与最终点共用 |
| 圆弧中间点 | `intermediate_waypoint_tolerance_m` | `0.40 m` | 是 |
| DIG/DUMP 最终点 | `waypoint_tolerance_m` | `0.25 m` | 否，与起点共用 |

代码当前对轨迹的第一个 waypoint 和最后一个 waypoint 使用
`waypoint_tolerance_m`，其余 waypoint 使用
`intermediate_waypoint_tolerance_m`。因此现在是“两级容差”，不是三个完全独立的容差。

实时起点由当前斗尖位置生成，生成时距离基本为零，通常首帧就会通过。现场调参主要影响中间点和最终点。

## 2. 调整起点容差

### 当前能做什么

修改 `waypoint_tolerance_m` 会同时改变起点和最终点，不能只改变起点：

```json
"limits": {
  "waypoint_tolerance_m": 0.25
}
```

权威文件：

```text
/home/zhaoshuai/workspace_uinty/RL_prj/AiryLidar/mission/config/excavation_cycle.json
```

为了让历史 PC Mission/Demo 路径保持相同限制，还应同步修改：

```text
/home/zhaoshuai/workspace_uinty/RL_prj/AiryLidar/mission/config/excavation_demo.json
```

### 如果必须让起点独立

仅修改 JSON 做不到。需要新增并贯通
`start_waypoint_tolerance_m`：Mission/Target Catalog schema、候选生成器、轨迹 SHA、Orin loader 和 `WaypointTracker` 都要一起修改并测试。

目前不建议这样做，因为实时起点天然等于生成轨迹时的斗尖位置，单独放宽起点通常没有实际收益。

## 3. 调整最终点容差

在以下两个文件中修改同一个 `waypoint_tolerance_m`：

```text
/home/zhaoshuai/workspace_uinty/RL_prj/AiryLidar/mission/config/excavation_cycle.json
/home/zhaoshuai/workspace_uinty/RL_prj/AiryLidar/mission/config/excavation_demo.json
```

例如恢复为 `0.25 m`：

```json
"limits": {
  "waypoint_tolerance_m": 0.25,
  "waypoint_dwell_s": 0.0,
  "tracking_timeout_s": 60.0,
  "settle_s": 0.5
}
```

含义：斗尖到当前最终 waypoint 的三维欧氏距离小于等于 `0.25 m` 时，该最终点判定到达。

注意：

- 数值越小，最终位置越精确，但更容易因液压死区或策略收敛能力不足而停留、超时。
- 数值越大，任务更容易完成，但可能在离目标较远时提前切换 Behavior。
- `targets.*.radius_m` 必须大于等于 `waypoint_tolerance_m`，否则 Mission 严格校验会拒绝配置。
- 调整最终点容差不能修复持续单向满幅 swing、错误观测或错误目标坐标。

## 4. 调整圆弧中间点容差

当前四套 V3-B Mission 都由同步脚本统一传入中间点容差。编辑：

```text
/home/zhaoshuai/workspace_uinty/RL_prj/excavator-il/scripts/sync_v3b_dig_catalog.py
```

在 `_build_deployments()` 调用参数中找到：

```python
"--intermediate-waypoint-tolerance-m",
"0.40",
```

只修改第二行数值。例如改成 `0.35 m`：

```python
"--intermediate-waypoint-tolerance-m",
"0.35",
```

约束：

- 必须为有限正数。
- 当前生成器要求中间点容差不小于 `waypoint_tolerance_m`。
- 中间点只是引导回转趋势，通常应比最终点宽松，避免机械地精确追逐中间点造成停顿。
- 该数值会进入生成的 Target Catalog 和轨迹摘要，修改后必须重新生成，不能只重启 UI。

## 5. 修改后的生成与双端同步

不要直接编辑以下生成物：

```text
excavator-orin-runtime/deploy/v3b/**/target_catalog.candidate.json
excavator-orin-runtime/deploy/v3b/**/fixed_cycle.candidate.json
```

`fixed_cycle.candidate.json` 保存了 Target Catalog 的 SHA-256。直接改其中一个文件会造成摘要不一致，Mission 会在打开运动资源前拒绝启动。

先验证源 JSON：

```bash

python3 -m json.tool AiryLidar/mission/config/excavation_cycle.json >/dev/null
python3 -m json.tool AiryLidar/mission/config/excavation_demo.json >/dev/null
```

确认 Orin 没有 Mission、Collector 或 ACT worker 占用串口和相机：

```bash
cd /home/zhaoshuai/workspace_uinty/RL_prj/excavator-il
conda run -n excavator-il --no-capture-output \
  python scripts/sync_v3b_dig_catalog.py --check-idle
```

预期输出：

```json
{
  "status": "orin_idle"
}
```

然后重新生成四套 Mission 候选并同步 PC/Orin：

```bash
conda run -n excavator-il --no-capture-output \
  python scripts/sync_v3b_dig_catalog.py
```

该命令会更新：

- `fixed_target_hybrid`
- `classical_tracking_hybrid`
- `fixed_dig_hybrid`
- `engineering_act_transport_reference`

同步脚本会先在 PC 和 Orin `/tmp` 建立可恢复备份，再发布新候选并核对摘要。

## 7. 生效条件与真机验证

Resident Mission 启动时把 Plan 和 Target Catalog 冻结到内存，不支持运行中热更新。同步后必须：

1. 停止旧 Mission；
2. 重新启动 Web UI；
3. 重新点击启动任务；
4. 先在发动机关闭状态检查日志中的 `tolerance_m`；
5. 再按单铲、小批次顺序进行真机验证。

日志预期：

```text
中间点 waypoint=2/3 ... tolerance_m=0.4000
最终点 waypoint=3/3 ... tolerance_m=0.2500
```

如果日志仍显示旧值，说明运行中的 Mission 没有重启，或者 Orin 候选目录尚未同步。

## 8. 推荐现场基线

当前经过较多真机运行的推荐基线是：

```text
起点与最终点：0.25 m
圆弧中间点：  0.40 m
```

一次只修改一个容差，并保留对应 Experiment Run、日志、配置 SHA 和操作者观感。不要同时修改 waypoint、RL 模型、启动斜率和到达容差，否则无法判断效果来自哪一项变化。
