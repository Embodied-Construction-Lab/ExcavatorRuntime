# 数据、训练与实验评估

## 200 条采集 Campaign

默认计划为 20 个土壤重置 block × 每块 10 条，共 200 条；任务在 `dig_only` 与 `dig_transport_dump` 间分块组织，挖点按 `dig_01/02/03` 循环。诊断 Episode 单独标记并忽略，不推进 Campaign。

## 原始数据

每个正式 Episode 包含：

- `front`、`dump` 两路 RGB；
- STM32 原始遥测与 11 维状态；
- 专家四维动作；
- task/soil/dig/operator/material；
- AiryLidar 目标文件 SHA、commit 与坐标 provenance；
- quality report。

## 训练集切分

必须按 `source.soil_reset_block_id` 分组切分，并按任务类型分层。一个 block 内所有 Episode 只能进入同一 partition。旧数据没有 block 时才退回按 source Episode 分组。

## Experiment Run

Experiment Run 固化：仓库 commit/dirty 状态、配置和机器 profile、策略模型、任务上下文、事件、日志和 artifact 快照。外部 `source_path` 只用于追溯，Run 内 `snapshot_path` 才是后续评估的权威字节。

## Evaluation Harness

统一评估需要覆盖：

- 任务成功率、单铲/整周期时间；
- 装载质量与卡车装满所需铲数；
- RL 端点/轨迹误差与规划成功率；
- ACT 动作完成率和人工接管；
- RL↔ACT handoff p50/p95/max；
- 相机频率、状态/图像 age、掉帧和安全归零事件；
- 按任务、挖点和土壤 block 分组结果。

同一 Harness 用于 ACT vs Diffusion Policy、ONNX RL vs 传统控制器及后续消融实验，避免每种策略自行定义“成功”。
