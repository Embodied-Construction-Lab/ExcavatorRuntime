# 数据、训练与实验评估

## 当前采集方式

Web UI 一次点击只创建一条 Episode。200 条是离线实验目标，不是 Runtime 自动循环：

- 第一阶段：约 100 条 `dig_only`；
- 第二阶段：约 100 条 `dig_transport_dump`；
- 失败、中止和诊断 Episode 保留作审计，但不进入训练候选集；
- 区域、重复次数和备注只作为人工标签，不控制 Episode 编号或运动生命周期。

2026-08-26 第一阶段快检结果：110 个目录中 104 条有效，13,007 个训练 step，约
13 GB；全部为 `dig_only`。两路相机约 30.22 Hz、STM32 约 19.64 Hz、状态约
9.84 Hz、动作约 20 Hz；有效数据中 parse/write/sensor/queue/disk failure 均为 0。

当前转换后的两类训练集必须保持分开：

| 数据任务 | 输入相机 | source Episode | 训练/验证 | 训练/验证 frame |
|---|---|---:|---:|---:|
| `dig_only` | front only | 104 | 83 / 21 | 10,436 / 2,571 |
| `dig_transport_dump` | front + dump | 35 个唯一 source | 28 / 7 | 5,737 / 1,424 |

2026-08-27 正在执行的训练顺序是：先训练 front-only、swing-zero 的 400K-step
`dig_only` ACT（seed 2027），再训练 300K-step 双 RGB `dig_transport_dump` ACT，最后对
checkpoint 做离线评价。训练过程中不要再启动第二个大型 GPU 任务，也不要移动正在写入的
output 目录。

## 原始数据

每个正式 Episode 包含：

- `front`、`dump` 两路 RGB；
- STM32 原始遥测与 11 维状态；
- 专家四维动作；
- task/soil/dig/operator/material；
- AiryLidar 目标文件 SHA、commit 与坐标 provenance；
- quality report。

## 训练集切分

严格标注的数据必须按 `source.soil_reset_block_id` 分组切分，并按任务类型分层。一个
block 内所有 Episode 只能进入同一 partition。

本次 104 条 `dig_only` 没有按权威规则维护 block/zone，不能把重复的 `block_01` 当成
真实分组，也不应据此宣称跨土壤泛化。推荐把它们用于训练，在之后另采严格标注的 held-out
评估集；若仅做工程初测，可按 source Episode 切分，但报告中必须说明相邻土壤状态可能带来
乐观偏差。

`dig_transport_dump` 的转换结果需要在论文 corpus 冻结前审计 source
`episode_0143` 的重复索引。现有 grouped split 没有把该 source 放入两个 partition，
但 manifest 中必须解释重复产生原因和最终保留规则。

## Experiment Run

Experiment Run 固化：仓库 commit/dirty 状态、配置和机器 profile、策略模型、任务上下文、事件、日志和 artifact 快照。外部 `source_path` 只用于追溯，Run 内 `snapshot_path` 才是后续评估的权威字节。

## Evaluation Harness

统一评估需要覆盖：

- 任务成功率、单铲/整周期时间；
- 装载质量与卡车装满所需铲数；
- RL 端点/轨迹误差与规划成功率；
- ACT 动作完成率和人工接管；
- RL↔ACT handoff p50/p95/max；
- 相机频率、状态/图像 age、掉帧和安全归零事件；
- 按任务、挖点和土壤 block 分组结果。

同一 Harness 用于 ACT vs Diffusion Policy、ONNX RL vs 传统控制器及后续消融实验，避免每种策略自行定义“成功”。

论文 R01–R12、state-only ACT、逐铲称重、TADPS 对照和正式 block 设计见
[ICRA 2027 证据与开发路线](../论文与实验/ICRA2027证据与开发路线.md)。
