## 一、本阶段目标

本阶段的核心不是继续叠加独立脚本，而是把 RL、ACT、经典控制和固定动作拆成可替换 Behavior，
由声明式 Mission 统一编排；同时稳定 IMU/STM32/遥测链，并把论文消融、TADPS 和 RL sim-real 的
证据生产工具准备完整。

## 二、为什么本周必须先做这些工作

1. **从演示转向可归因实验**：此前多铲成功证明系统具有工程可行性，但没有隔离目标选择、轨迹跟踪和
   挖掘策略。声明式 Mission 使实验只替换一个 Behavior，差异才能归因到相应方法。
2. **先保证观测可信**：RL 是闭环策略，yaw、关节状态或 fault 状态错误会直接改变输出。IMU 和 STM32
   排障不是外围维护，而是算法实验成立的测量前提。
3. **把安全停机与算法失败分开**：安全门拒绝危险遥测是正确行为。保留撤权原因和终态零 ACK，既保护
   真机，也避免把硬件 fault 误归因于 RL/ACT 的算法效果；该次运行仍作为失败 attempt 保留在分母中。
4. **把视频观感变成机器可读证据**：论文需要样本身份、失败分母、误差、耗时和版本，而不是“看起来
   更丝滑”。trace、Experiment Run 和 attempt manifest 正是为这一转换服务。
5. **先仿真排除工具问题，再使用真机**：Unity 批量运行验证了场景和记录工具的重复性，减少真机现场
   才发现证据缺失的风险；但仿真不能替代真实液压与土体实验。

## 三、主要进展

### 1. 软件架构从“任务分支”收敛为“Mission 编排 Behavior”

- `Mission Definition` 负责描述任务配方；`Mission Scheduler` 负责按结果推进状态机；Policy/Controller
  作为独立 Behavior；Resident Motion Core 保持唯一运动权威。
- RL、ACT 和固定动作的物理语义不同，但统一映射到轴顺序
  `[boom, stick, bucket, swing]`，经各自 Adapter 后进入同一安全执行边界。
- Mission、目标 catalog、PC runtime、Owner READY、ACT behavior/checkpoint 和 Experiment Profile
  通过 ID 与 SHA-256 绑定，减少实验身份漂移。
- 当前论文 live 参考链只改变一个因素：固定点混合基线、经典跟踪替代 RL、固定挖掘替代 ACT。

### 2. 真机主线恢复并保留 fail-closed 安全边界

- 修复 Owner READY 真实日志解析问题，完成发动机关闭启动/停止验证。
- 但硬件 READY 打印目前尚未把当前帧 STM32 `fault_flags` 合入判定，故现场仍必须同时确认
  `sensor_valid=true` 与 fault flags=0；不能只凭 READY 字样启动运动。
- 通过 action audit 区分了“策略切换失败”和“STM32 遥测不安全撤权”；`MOTION_GATE_CLOSED`、
  `ACT_AUTHORITY_LOST` 均确认是安全结果而非错误继续运动。
- 最近的 DWJ/PCA/I²C fault、STM32 未上电、坏 CSV 和 `sensor_valid=false` 均形成可追溯诊断路径。
- UI 机构遥测与 ACT/相机预览解耦，展示链继续保持只读，不参与运动决策。

### 3. IMU 与回转问题形成可回滚基线

- 对静止 yaw 漂移完成定量复测和启动零偏补偿实验。
- 新补偿虽显著降低短时漂移，但现场出现回转状态失配风险，因此重要演示使用
  `zs/imu-baseline-ab`。
- 在基线增加相对上电方向的 `±180°` 低层回转保护；该保护是最后边界，不替代正确的状态估计、
  RL 目标跟踪或绝对航向参考。

### 4. 论文实验矩阵与证据工具基本齐备

- 三个 live 条件已经有独立 Mission、Runtime、UI 和 Evidence Profile，状态为 commissioning。
- RL sim-real 已有 Unity/Orin producer、canonical trace v3、parent Run、pair、attempt manifest 和
  aggregate；失败、timeout、intervention 和缺失 pair 都有明确分母语义。
- TADPS 已有完整候选 logger、capture、export 和离线 evaluator，支持 highest-point、score-only、
  full TADPS 对比，且默认关闭、无运动权限。
- 建立静态 readiness inspector，当前真实结果仍是 `3 commissioning / 3 planned / 0 ready`。

### 5. RL 仿真侧取得首批可复现实验资产

- 建立专用 Unity 实验 Scene 和 EditMode 契约测试。
- 当前 RL 模型完成 5 点单轮、pilot 和 5 轮预冻结重复实验。
- 正式重复部分为 25 个任务、50 个跟踪段，全部完成；50 个 simulation parent Run 均保存模型、
  suite 和 trace artifact。

## 六、本周解决的关键问题

1. 消融实验不再复制整套状态机，只通过声明式 Mission 替换 Behavior。
2. PC READY parser 与 Orin 真实 logging 格式不一致导致的启动失败已修复。
3. UI 机构状态不再依赖 ACT worker/相机预览生命周期。
4. IMU 零偏、环绕角、动态状态和显示链问题被拆开；建立了可回滚固件分支和低层保护。
5. RL 仿真不再只看 Unity 画面，形成了 10 Hz 策略样本、真实跟踪状态、终态和 provenance 证据。
6. TADPS 不再依赖旧的 selected-point 日志，具备完整 preselection candidate 的冻结链路。

## 七、仍未关闭的事项

1. 真机回转偶发过转的完整根因尚未由同步的“观测→策略输出→Orin 下发→STM32 执行→实际姿态”
   时间线最终关闭；F407 限位只能控制最坏后果。
2. 三个 live commissioning 条件还缺统一的发动机关闭、单铲、多铲和正式 soil-reset/称重 block。
3. RL sim-real 只有仿真侧 50 段；真实机 trace、pair report 和 complete aggregate 尚未生成。
4. TADPS 真实候选 replay、held-out split 和 live Resident Mission 绑定尚未完成。
5. ACT 挖掘—运转—倾倒模型存在提前 swing、挖掘不明显等行为；它只作工程参考，暂不继续真机放大。
6. RLExcavator 仍有未推送提交和用户本地大资产；部分仿真 parent 如实记录 dirty provenance。正式论文
   冻结前应先提交/推送允许的源码，再决定是否复跑。
7. `RESIDENT_HARDWARE_READY` 与 STM32 fault flags 的原子一致性尚未关闭；正式现场 Gate 前需修复并以
   fault 注入回归验证。

## 八、本周结论

这四天完成了从“为每个实验临时改状态机”到“同一安全执行框架内组合独立 Behavior”的结构性
收敛，并拿到了 RL 固定点仿真的首批成批结果。当前最成熟的是固定点混合主线和仿真证据生产链；
最缺的是现场 matched block、真机 tracking trace 和 TADPS 真实输入。下一阶段应停止大范围重构，
优先把这些已有入口转化为正式、可统计、可写入论文的证据。
