# 相机：设备、预览与双路采集

## 当前用途

| 角色 | 用途 | 当前在线策略 |
|---|---|---|
| `front` | 挖掘区、铲斗与土体 | 当前 ACT 单相机输入 |
| `dump` | 运转、卡车与倾倒区 | 双路采集；为后续完整挖运倒策略准备 |

两路均由 Orin 上同一个 Collector 独占采集，配置为 640×480@30 Hz。Web UI 只读取 MJPEG 预览，不会重复打开 UVC 设备。

## 稳定设备名

活动配置使用 `/dev/v4l/by-path/...`，不要长期写死 `/dev/video0`、`/dev/video2`，因为 USB 枚举顺序可能变化。

```bash
ls -l /dev/v4l/by-path/
v4l2-ctl --list-devices
```

Docker `--device` 不能直接可靠解析包含冒号的 by-path。项目 launcher 会先通过 `readlink -e` 解析成真实 `/dev/videoN`，再映射到容器内固定设备名。

## 预览

Collector 启动后：

```bash
curl -fsS http://192.168.50.2:18092/healthz
```

Web UI 中两路画面上下排列。Collector 未启动时显示“等待 Collector”是正常状态。

## 采集前验收

1. 设备路径存在且两个角色没有指向同一物理设备。
2. 两路约 30 Hz，分辨率与配置一致。
3. 图像不接近全黑/全白，JPEG 可解码。
4. 人工确认镜头无遮挡、无强反光，尤其是倾倒相机。
5. `fuser` 显示没有未知 Owner。

```bash
fuser -v /dev/video0 /dev/video2 2>&1 || true
```

## 常见问题

- UI 无画面但未启动 Collector：正常。
- Collector 已运行仍无画面：查 18092、相机 by-path、UVC 打开日志和设备 Owner。
- 倾倒画面红/黑：优先调整物理安装、遮挡和曝光，不用软件增强掩盖坏数据。
- ACT 推理只看 `front`：这是当前部署契约，不代表第二路采集无用；新数据会支持未来完整挖运倒策略。
