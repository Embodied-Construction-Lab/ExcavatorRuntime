# 诊断笔记：从无运动到根因

诊断原则：先只读、再零命令、最后才允许运动；一次只启动一个硬件 Owner。保留完整日志，不通过放宽 timeout 或 freshness 门限掩盖问题。

## 1. 固定诊断顺序

### 1.1 网络和配置

```bash
ping -c 5 192.168.50.2
ssh -o BatchMode=yes -o ConnectTimeout=5 jetson16@192.168.50.2 'hostname; date --iso-8601=seconds'

cd /home/zhaoshuai/workspace_uinty/RL_prj/excavator-il
conda activate excavator-il
python scripts/check_site_config.py
```

### 1.2 资源 Owner

在 Orin：

```bash
fuser -v /dev/ttyTHS1 /dev/video0 /dev/video2 2>&1 || true
pgrep -af '[o]rin_state_sender|[r]esident_act_runtime|[e]xcavator-il collect' || true
```

未知 PID 先查看完整命令和启动者，不直接全局杀进程。

### 1.3 STM32 只读链路

```bash
python scripts/diagnose_stm32_link.py
```

通过标准：`passed=true`、解析失败 0、序号间断 0、18～22 Hz、最大接收周期不超过 80 ms。

### 1.4 零命令 soak

发动机关闭、双杆回中、deadman 释放：

```bash
python scripts/run_zero_command_soak.py
```

通过标准：非零命令/回显/有效动作均为 0；STM32 约 20 Hz，新状态约 10 Hz，两路相机约 30 Hz。

## 2. 现象 → 根因 → 处理

| 现象/错误 | 常见根因 | 处理 |
|---|---|---|
| STM32 `must be ASCII`、字段不是 55、NUL/乱码 | 充电器导致链路断开，或串口电气状态异常 | 拔掉充电器，重启 STM32/Orin 后先跑只读诊断 |
| `serial is already owned` / `Could not exclusively lock` | RL、Collector 或 ACT 重复启动 | 用 `fuser`/`pgrep` 找具体 Owner，通过原 UI/终端正常停止 |
| `sensor_valid=false`、新状态 0 Hz | STM32 未复位、传感器链路失效或仍在充电 | 检查供电/充电器、复位 STM32，再诊断 |
| `/joint_states` 无数据 | Orin 状态流、UDP 18081 或 PC bridge 未运行 | 查 Orin Runtime、端口和 Operator profile |
| JointState 有但 RViz 某关节不动 | 映射、单位、关节名或 URDF/TF 问题 | 对照 Web UI 原始角度与 `/joint_states`，逐关节检查 |
| `local_map.timestamp_s 已过期或来自未来` | PC/Orin 时间不同步，或 LocalMap 没有新数据 | 检查 Chrony/systemd-timesyncd，再查感知栈 |
| `live planning inputs did not become fresh` | AiryLidar Operator/雷达/地图没启动或时间戳失效 | 启动 `live_commissioning`，逐级查点云→地图→状态 |
| UI 无相机，显示“等待 Collector” | 未启动 Collector 时属正常；运行中则是 18092/设备 Owner 问题 | 查 `/healthz`、相机 Owner 和 by-path 设备 |
| `docker: bad format for path ...by-path...:/dev/video0` | USB by-path 名含冒号，直接传给 Docker 解析歧义 | 当前脚本已先 `readlink -e` 为 `/dev/videoN`；确认 Orin 代码已同步 |
| import-only Docker 检查提示 `NVIDIA Driver was not detected` | 命令未传 GPU，仅做 Python import | 属正常；真推理用项目 launcher 并运行 GPU 诊断 |
| ACT `Found no NVIDIA driver` | 真推理容器未注入 NVIDIA Runtime | `bash scripts/diagnose_orin_gpu_access.sh`，检查 Docker runtime |
| 安全停止后又报 `terminal disarm ... request failed` | 旧版本重复发送 terminal disarm，第一次已关闭 socket | 更新到含幂等 disarm 的版本；最新回归已通过 |
| Orin Git push 连接 `192.168.31.219:7897` 失败 | Orin 仍配置旧 Wi-Fi 局域网代理 | 项目同步走 PC push + 有线 bundle；需要外网时再单独修代理 |
| GitHub/SSH 能 ping 但 SSH 旧地址断开 | Orin Wi-Fi 地址变化 | 使用稳定有线地址 `192.168.50.2` |
