# 理解笔记：端到端架构与核心代码

## 1. 一句话介绍项目

这是一个面向真实液压挖掘机的分层自主作业系统：PC 负责三维感知、目标与轨迹规划，Orin 常驻运行 RL 轨迹控制器和视觉模仿学习策略，STM32 负责确定性低层控制与安全边界；Mission 在同一硬件 Owner 内把“到挖点—挖掘—运转倾倒—返回”组织成闭环任务，并为论文实验保存可复现证据。

## 2. 五个主要仓库

| 仓库 | 责任 | 面试/汇报关键词 |
|---|---|---|
| `AiryLidar` | 雷达、TF、LocalMap、规划、RViz、Mission | 3D 感知与任务规划 |
| `excavator-orin-runtime` | STM32 唯一 Owner、RL Controller、Resident authority | 实时控制与失效归零 |
| `excavator-il` | 双相机采集、Web UI、ACT/DP Seam、训练、评估 | 模仿学习与实验系统 |
| `RLExcavator` | Unity/AGX 强化学习与 ONNX 导出 | Sim-to-real RL |
| `F407` | STM32 固件、命令协议、限位和 watchdog | 嵌入式低层控制 |

跨仓契约在 `shared/machine_profile.json`；动作顺序、速度尺度和观测定义不能由某一仓单独改写。

## 3. 两条闭环

### 3.1 RL 轨迹闭环

```text
RoboSense 点云
→ LocalMap / OctoMap
→ 固定点轨迹（V3-A 在 Orin 本地；V2 由 PC Plan 生成）
→ Orin Trajectory Controller（ONNX RL 或传统控制器 Seam）
→ VELOCITY_REFERENCE
→ STM32
→ 机构状态回到 Orin/PC
```

RL 不直接“追一个大球”，而是依据 38 维观测和未来 waypoint 生成 `[boom, stick, bucket, swing]` 物理速度。中间 waypoint 与端点可使用不同到达容差。

### 3.2 ACT 挖掘闭环

```text
前视 RGB + 11 维机构状态
→ Dig Policy（当前 ACT，未来可替换 Diffusion Policy）
→ MANUAL_ACTION 杆量
→ STM32
→ 新图像/状态滚动推理
```

当前已部署 ACT 是单相机推理；第二台倾倒相机先用于新数据采集，为后续“挖掘—运转—倾倒”策略提供视觉信息。Dig Policy Seam 让 ACT/DP 共享相同输入输出契约，策略不持有串口。

## 4. 为什么 Resident 架构能快速切换

旧流程每段都重新启动进程、加载 ONNX/ACT 和申请硬件，冷启动导致明显停顿。Resident 架构将职责拆开：

- Resident owner 始终是唯一串口 Owner；
- ACT Worker 提前加载模型和 CUDA，但没有运动权限；
- RL Controller 资产提前加载；
- 控制面只切换 `control_generation` 和活动 source；
- 旧 source 先由 STM32 遥测确认零命令，目标 source 再取得 authority；
- candidate 过期、链路断开、安全状态失效都 fail closed 到零。

因此真正的切换成本主要是终态零 ACK、目标第一条有效动作和规划准备，而不是模型加载。

V3-A 进一步把固定 DIG/DUMP 轨迹和 Mission 状态机放到 Orin：PC 掉线时由
heartbeat lease 过期触发归零，正常阶段交接不再等待 PC 启动子进程或在线规划。
这个版本的短期边界是“固定挖点 + Orin 本地常驻闭环”，不包括自动挖点选择。

## 5. 状态如何进入 RViz

```text
STM32 CSV
→ Orin machine_state_v1
→ UDP 18081
→ AiryLidar pc_runtime_bridge
→ /joint_states
→ robot_state_publisher + waji.urdf
→ TF 关节链
→ bucket_tip_pose_publisher
→ /bucket_tip_pose_machine_root_ros
```

`/joint_states` 有数据但模型不动时，要区分：关节名称/单位错误、URDF/TF 断链、某一关节（如 bucket）映射错误，以及时间戳陈旧。

## 6. Mission 与安全边界

Mission 描述“做什么”，策略描述“怎么动”，STM32 决定“命令是否能安全执行”。典型一铲：

```text
RL 到 DIG → ACT 挖掘 → RL 到 DUMP → 固定动作倾倒 → RL 返回下一 DIG
```

所有非零路径都需要显式运动授权和有效 `control_enabled`。安全停止、租约过期、Worker 断开、候选过期、命令乱序或传感器失效都必须归零，不能沿用上一条非零命令。

## 7. 数据与论文证据

原始 Episode 保存双 RGB、STM32、本体状态和专家动作；正式数据还绑定任务类型、土壤重置批次、挖点、操作者、目标配置 SHA 和仓库 commit。Experiment Run 对配置、模型、日志和评估产物做不可变快照，Evaluation Harness 使用统一指标比较 ACT/DP、RL/传统控制器及消融实验。

训练/验证必须按 `soil_reset_block_id` 分组切分，不能让同一土壤状态的相邻 Episode 跨训练集和验证集，否则会产生数据泄漏。

## 8. 介绍项目时的三层讲法

1. **问题层**：土体交互难建模，单一策略难同时做好自由空间运动与接触挖掘。
2. **方法层**：RL 负责几何轨迹跟踪，视觉模仿学习负责接触技能，Resident Mission 用安全 authority 进行快速切换。
3. **实验层**：真实挖掘机、双相机示教、土壤块分组、统一 Evaluation Harness，对比学习策略与传统基线，并报告任务成功率、周期、装载质量、切换时延和安全事件。
