## 1. 系统边界

```text
PC / AiryLidar：雷达、地图、RViz、Web UI 与 Experiment Run 证据
Orin：唯一 STM32 Owner、固定点轨迹、V3-A Mission、RL/ACT 推理、相机与采集
STM32：20 Hz 低层控制、限位、watchdog 与遥测
```

权威动作顺序始终是 `[boom, stick, bucket, swing]`；状态字段中的 `arm` 与控制字段中的 `stick` 是同一个自由度。

## 2. 上电与安全检查

1. 作业区无人，硬件急停可用。
2. 双杆全部回中，deadman 未按。
3. 首次 Shadow/短动作验收保持发动机关闭。
4. **拔掉挖掘机充电器**。当前机器充电会断开 STM32 与挖掘机侧链路，造成乱码、字段数错误或 `sensor_valid=false`。
5. PC–Orin 控制网线已连接；优先使用 `192.168.50.2` SSH，不依赖 Wi-Fi 地址。
6. 不手工并行启动 Collector、`orin_state_sender.py` 和 ACT Runtime；它们会竞争串口或相机。

## 4. 当前 V3-A 总入口

```bash
python scripts/run_collection_ui.py \
  --config config/collection_ui.v3a-commissioning.pc.json
```

不自动打开浏览器时追加 `--no-browser`。浏览器打开
`http://127.0.0.1:8088/`。当前使用 commissioning 配置，是因为 V3-A 固定轨迹
尚在真机验收。完成 1 铲、3 铲及安全停止验收并晋升 field 轨迹后，才恢复
无 `--config` 的日常入口。

页面提供：

- RL 到挖点、人工预定位、直接采集和仅遥操作；
- 前视/倾倒双 RGB 预览和 STM32 状态；
- V3-A 自动执行 1～9 铲，挖点按 `dig_01 → dig_02 → dig_03` 循环；
- “安全停止”执行本轮 Owner 的终态归零与资源释放。

V3-A Mission 时 Orin 不需要手工启动任何 Runtime。UI 只负责启动、取消、
状态显示与 heartbeat；固定轨迹和 RL/ACT 阶段切换均在 Orin 常驻 Owner 内完成。
当前 V3-A 会在自动 Mission 前启动 PC `live_shadow` RViz，只读显示真机
状态、雷达和 Orin 实际正在跟踪的三点轨迹。PC 不生成轨迹、不启动
Behavior Gateway，也不发送运动命令。页面可先点“启动 RViz 显示”；首次验收
必须保持发动机关闭，确认红色轨迹线与黄色 waypoint 正确后再通电。

## 5. 推荐测试顺序

```text
只读 STM32 诊断
→ 零命令 soak
→ 发动机关闭：V3-A 启动后在 FOLLOW_DIG 点“安全停止”
→ 通电自动 1 铲
→ 通电自动 3 铲（覆盖 dig_01/02/03）
→ 通电自动多铲
```

每一级通过后再进入下一级。策略切换与多铲流程见 [Resident 双策略切换](软件与策略/Resident双策略切换.md)。

## 6. 正常停止

- UI 管理的任务：点击“安全停止”。
- 手工终端：按 `Ctrl+C`。
- 危险情况：使用硬件急停，软件停止不能代替急停。

停止后在 Orin 检查：

```bash
fuser -v /dev/ttyTHS1 /dev/video0 /dev/video2 2>&1 || true
pgrep -af '[o]rin_state_sender|[r]esident_act_runtime' || true
```

无输出表示串口、两台相机和 Resident 进程已释放。不要使用全局 `pkill` 或 `killall` 作为日常停止方式。

## 7. 正式采集与诊断数据

- Web UI 一次点击只创建一条 Episode，不会自动连续采集 200 条。
- 每条由操作者填写任务、土壤批次和挖点等标签，再人工选择成功、失败或重录。
- `run_zero_command_soak.py` 是 `diagnostic`，不能进入训练集。
- 每批正式采集前先运行双相机预检，并在 UI 中人工确认两路画面没有遮挡、过暗或过曝。
- 技术放行条件是 `status=complete && success=true` 且 raw validator 通过；页面人工点击
  “成功”不能替代技术校验。
