# 总笔记：现场启动与演示

这篇只保留最常用的正常路径。更细命令见 [相关命令](相关命令.md)，出现异常转到 [诊断笔记](诊断笔记.md)。

## 1. 系统边界

```text
PC / AiryLidar：雷达、地图、规划、RViz、Mission 与 Web UI
Orin：唯一 STM32 Owner、RL/ACT 推理、相机与采集
STM32：20 Hz 低层控制、限位、watchdog 与遥测
```

权威动作顺序始终是 `[boom, stick, bucket, swing]`；状态字段中的 `arm` 与控制字段中的 `stick` 是同一个自由度。

## 2. 上电与安全检查

1. 作业区无人，硬件急停可用。
2. 双杆全部回中，deadman 未按。
3. 首次 Shadow/短动作验收保持发动机关闭。
4. **拔掉挖掘机充电器**。当前机器充电会断开 STM32 与挖掘机侧链路，造成乱码、字段数错误或 `sensor_valid=false`。
5. PC–Orin 控制网线已连接；优先使用 `192.168.50.2` SSH，不依赖 Wi-Fi 地址。
6. 不手工并行启动 Collector、`orin_state_sender.py` 和 ACT Runtime；它们会竞争串口或相机。

继续条件：配置检查无错误；STM32 `passed=true`、解析失败和序号间断均为 0；零命令 soak `passed=true`、两路相机约 30 Hz、STM32 约 20 Hz、新状态约 10 Hz。

## 4. 推荐总入口

```bash
python scripts/run_collection_ui.py
```

浏览器打开 `http://127.0.0.1:8088/`。页面提供：

- RL 到挖点、人工预定位、直接采集和仅遥操作；
- 前视/倾倒双 RGB 预览和 STM32 状态；
- RL + ACT 分阶段验证；
- 自动执行 1～9 铲，挖点按 `dig_01 → dig_02 → dig_03` 循环；
- “安全停止”执行本轮 Owner 的终态归零与资源释放。

混合 Mission 时 Orin 不需要手工启动任何 Runtime。UI 负责启动 Resident owner、常驻 ACT Worker 和 AiryLidar Operator。

## 5. 推荐测试顺序

```text
只读 STM32 诊断
→ 零命令 soak
→ UI 仅遥操作
→ ACT/RL 分阶段验证
→ 自动单铲
→ 自动多铲
```

每一级通过后再进入下一级。策略切换与多铲流程见 [Resident 双策略切换](软件与策略/Resident双策略切换.md)。

## 6. 正常停止

- UI 管理的任务：点击“安全停止”。
- 手工终端：按 `Ctrl+C`。
- 危险情况：使用硬件急停，软件停止不能代替急停。

停止后在 Orin 检查：

```bash
fuser -v /dev/ttyTHS1 /dev/video0 /dev/video2 2>&1 || true
pgrep -af '[o]rin_state_sender|[r]esident_act_runtime' || true
```

无输出表示串口、两台相机和 Resident 进程已释放。不要使用全局 `pkill` 或 `killall` 作为日常停止方式。

## 7. 正式采集与诊断数据

- Web UI 的 200 条 Campaign 是正式 `demonstration` 数据，必须匹配权威 `slot`、土壤重置批次和挖点。
- `run_zero_command_soak.py` 与终端引导入口是 `diagnostic`，不会推进正式 Campaign，也不能进入训练集。
- 周三正式采集前先运行双相机预检，并在 UI 中人工确认两路画面没有遮挡、过暗或过曝。
