## 一、总目标

不再扩展新的任务类型，优先完成三件事：冻结可复现版本；完成三个 live 对照条件的现场 Gate 和
matched block；补齐 RL sim-real 真机侧与 TADPS 真实 replay。工程参考 ACT 全动作策略不进入论文主线。

## 二、为什么按这个顺序推进

1. **先冻结再测**：如果实验期间继续修改代码、点位、容差或模型，即使结果更好也无法判断改动来源，
   仿真与真机也无法形成合法配对。
2. **先测主线参考条件**：`fixed_target_selection` 是其他两个 live 消融的共同参照。它不稳定时直接测
   classical 或 fixed-dig，无法判断问题来自替换模块还是公共链路。
3. **先 commissioning，后正式 block**：发动机关闭、单铲和多铲用于确认入口及安全，不进入正式统计；
   只有 Gate 通过后才冻结 soil reset、点位顺序、attempt 数和称重方法。
4. **每次只替换一个因素**：classical tracking 只回答“RL Follow 是否有贡献”，fixed dig 只回答
   “ACT 挖掘是否有贡献”。不能在同一组里同时换目标、控制器和挖掘动作。
5. **sim-real 沿用已冻结 manifest**：仿真侧已经完成，下一步应补同一身份的真机 attempt，而不是重新
   挑选更容易的点位。这样才能报告真实 domain gap 和失败分母。
6. **TADPS 先做离线组件消融**：目标选择器尚不需要获得运动权限。先用同一真实 replay 比较三种算法，
   可以用更低风险回答评分与时间稳定机制是否有效。

这套顺序的目的不是把工程做得更复杂，而是用最少的现场重复，得到能够解释“哪个模块带来什么收益”
的证据。

## 三、优先级

### P0：冻结实验版本与现场预检

1. 显式审查并提交当前允许入库的源码、Scene、测试和笔记；排除 AGX/imported 大资产、模型、日志、
   coverage 和历史 deploy 运行文件。
2. push `RLExcavator` 当前 ahead 的两个提交及专用实验 Scene/测试；记录五仓分支、HEAD 和 dirty 状态。
3. 重新运行静态 inspector，保存 Profile、Mission、catalog、machine profile、RL ONNX、ACT checkpoint
   和 F407 固件 SHA。
4. 修复并回归硬件 READY 与 STM32 fault flags 的同帧一致性；READY 不得在非 timeout fault 下出现。
5. 发动机关闭检查 STM32 约 20 Hz、`sensor_valid=true`、fault flags 为 0、终态零 ACK、资源唯一 Owner、
   相机/串口无竞争。

**停止条件**：持续 `sensor_valid=false`、坏 CSV、yaw 动态异常、terminal-zero 未确认、版本/hash 不一致。

### P0：完成三个 live 条件的 Gate

严格按风险顺序执行，每项先发动机关闭，再 1 铲，再多铲：

1. Profile `fixed_target_selection`（Mission `fixed_target_hybrid`）：重新建立架构调整后的稳定参考结果；
2. Profile `classical_tracking`（Mission `classical_tracking_hybrid`）：只替换 RL Follow，确认
   Cartesian-P 无危险振荡/超调；
3. Profile `fixed_dig`（Mission `fixed_dig_hybrid`）：只替换 ACT Dig，确认固定动作 artifact、时序和终态。

每个 attempted scoop 都保留，不把失败、timeout 或 intervention 删除。完成 commissioning 后再冻结
正式 soil-reset block 的条件顺序、点位顺序、attempt 数和统计方法。

三项 Gate 分别回答：公共硬件/安全链是否稳定；经典控制替换 RL 后是否能安全跟踪；固定动作替换 ACT
后是否能按相同任务契约完成。Gate 只判断“能否进入正式实验”，不用于选择看起来更好的条件。

### P0：运行 matched 论文 block

- Block A：Profile `fixed_target_selection` ↔ `classical_tracking`，即 Mission
  `fixed_target_hybrid` ↔ `classical_tracking_hybrid`，验证 RL 跟踪贡献；
- Block B：Profile `fixed_target_selection` ↔ `fixed_dig`，即 Mission
  `fixed_target_hybrid` ↔ `fixed_dig_hybrid`，验证 ACT 挖掘贡献。

同一 block 内交替或配对执行，记录：任务成功/失败、跟踪时间、端点误差、整周期时间、称重、timeout、
人工干预、原始日志、模型/config/Git hash。不要用工程演示日志补正式样本。

Block A 的因变量重点是跟踪完成率、端点误差、耗时和控制稳定性；Block B 的因变量重点是挖掘成功率、
单铲质量、动作时间和人工干预。两组都记录完整周期结果，但主要结论必须与被替换因素对应。

### P1：完成 RL sim-real 真机侧

1. 先选预冻结 manifest 的少量 attempt 做真机 pilot，验证 Orin 能生成无丢样的 canonical trace v3。
2. pilot 通过后再按 manifest 顺序采集 MoveToDig/CarryMaterial 真机 trace；失败也占原分母。
3. 为每个 attempt 生成 real parent Run 和 pair report；最后由预冻结 manifest 生成 aggregate。
4. aggregate 必须报告 common-prefix tracking、双方尾段/coverage、duration、terminal outcome 和缺失 pair，
   不能只比较命令相似度。

若 50 个真机段在论文截止前成本过高，先完成预注册 pilot 并如实报告样本量，不临时删除难点位。

### P1：采集并评估 TADPS 真实 replay

1. 在无运动条件下启用只读 complete-candidate logger，采集真实 LocalMap 候选帧；
2. 停止 selector 并等待 topic 静默后结束 capture，冻结原始 JSONL、descriptor、patch 和 SHA；
3. 建立 held-out sequence split；
4. 在完全相同 replay 上比较 highest-point、score-only 和 full TADPS；
5. 输出 terrain-valid rate、dropout、目标位移、switch rate、runtime，以及独立的 planner accept/reject。

本周不把 TADPS live 接入真机主线；先关闭组件级论文证据。

### P1：论文数据表和图

- 固化系统架构图：感知 → Frozen Target → 规划 → Mission/Behavior → Resident Motion Core → STM32；
- 建立三张待填表：live 对照、RL sim-real、TADPS component；
